# Движок интерьерных туров

Движок строит интерьер из файла данных `project.json`. Из одного файла получаются:

- 3D-тур в одном офлайн-HTML: прогулка, обзор, план, открывающиеся двери и фасады, палитры отделки, четыре режима света;
- выгрузка геометрии и проверки: пересечения, ход дверей, расстояния, проходимость, механизмы;
- план 1:50 (PDF A3 и SVG) и PDF-буклет с видами;
- лист шести видов для проверки изделия и фотореалистичные виды в Blender/Cycles.

Справочник прежнего формата interiors-engine/1. Для Lazy используется lazy-tour/1 и адаптер src/compile.mjs. Нейтральный шаблон: engine/projects/template-kabinet/. Клиентские проекты и прежний комплект текстур не включены. Команды ниже требуют отдельных зависимостей и своих карт; они не являются отчётом о проверке новой версии.

## 1. Быстрый старт

```bash
E=<папка навыка>/engine
cp -r $E/projects/template-kabinet /рабочая/папка/my-room     # проект — вне папки навыка
# правка my-room/project.json
python3 $E/make.py /рабочая/папка/my-room                       # тур, проверки, виды, план, буклет
python3 $E/make.py /рабочая/папка/my-room --steps build,export,check,docs   # быстро, без съёмки видов
```

Нужны Node.js 18+, Python 3 с numpy, reportlab, pypdf, Pillow и Playwright с Chromium. Проверить наличие зависимостей в текущей среде; не предполагать их установку. Для фоторендера дополнительно нужен Blender, см. раздел 9.

Результаты кладутся в `<проект>/out/`:
- тур `<id>-tour.html`;
- план PDF и SVG, буклет PDF;
- папка `data/`: `model.json`, `layout.json`, `routes.json`, `layout-report.json`, `verification.json`;
- папка `images/` с видами;
- `manifest.json` с размерами и SHA-256 файлов.

## 2. Папка проекта

| Файл | Что это |
|---|---|
| `project.json` | Обязательно. Стены, проёмы, двери, помещения, предметы, свет, виды, план, буклет, проверки |
| `custom.js` | Необязательно. Свои изделия проекта (раздел 5) |
| `textures/` | Необязательно. Свои текстуры; перекрывают одноимённые текстуры движка |
| `models/` | Необязательно. GLB-модели (раздел 7) |

Проекты пользователя хранить вне папки навыка. Пример в навыке менять только при изменении движка.

Для массового обновления материалов есть самостоятельный инструмент
`tools/materials.py`: упаковка карт, проверка полного исходного каталога и
целостности пакета. Формат manifest и границы проверки описаны в
[tour-upgrades.md](tour-upgrades.md). Он не подключает карты к `MAT` автоматически
и не входит в стандартный запуск `make.py`; адаптер и визуальная проверка остаются
частью конкретного проекта. Бренд и ассеты загрузочной заставки также хранить в
проекте, используя общий контракт готовности из этой ссылки.

## 3. Формат project.json

### Система координат

- Единицы — сантиметры (`"units": "cm"`). Ось x идёт вправо по плану, ось y — вниз по плану, высота отсчитывается от чистого пола.
- План строится по внутренним граням стен. `origin` — точка плана, которая станет центром сцены; обычно это середина помещения.
- Поворот `rot` задаётся в градусах вокруг вертикали. У кресел и стульев можно указать букву: `S` — сидящий смотрит в +y, `N` — в −y, `E` — в +x, `W` — в −x.

### Основные поля

| Поле | Значение |
|---|---|
| `schema` | `"interiors-engine/1"` |
| `meta` | `id` (латиница, имя файлов), `title`, `kicker`, `heading`, `version`, `date` (ГГГГ-ММ-ДД), `mark`, `loading`, `helpTitle`, `helpGo`, `helpExtra`, `storageKey` |
| `origin`, `ceiling`, `start` | Центр сцены [x, y]; высота потолка; id помещения, с которого начинается прогулка |
| `walls[]` | `id`, `a`, `b` — концы оси стены; `t` — толщина; `ops[]` — проёмы; `sides` — облицовываемые стороны; `range` — участок плинтуса по сторонам; `windows`; `mat`; `H`; `noSkirt` |
| `ops[]` стены | `type`: `door` / `window` / `arch` / `open`; `s`, `e` — от начала стены, см; у окна `sill`, `head`; у двери `head`; у арки `spring`, `rise` |
| `windows` стены | `inSide` (±1), `transom`, `sill` (материал подоконника), `noSill`, `blinds` — кассеты рулонных штор: `cassette` (отступ от грани), `cassetteZ`, `plane`, `top`, `overhang` |
| `overlays[]` | Облицовка грани стены: `wall`, `side`, `u: [u0, u1]`, `mat` (плитка, акцентная стена) |
| `floors[]`, `ceilings[]` | `poly` — точки плана; `mat`; `y` — подъём пола, см; `main: true` — пол, материал которого меняет панель «Отделка» |
| `doors[]` | `wall`, `op` (номер дверного проёма в стене), `hinge`: `s`/`e` (петли у начала или конца проёма), `swing` (±1 — сторона открывания), `angle`, `mat`, `style` (`plain`/`panel`/`glass`), `open`, `casing` (стороны наличников) |
| `rooms[]` | `id`, `name`, `rect`, `eye`, `look` — точка и направление прогулки; `hidden`, `quick` (быстрая кнопка без помещения), `eyeHeight` (122 — вид сидя); для плана `planColor`, `planRect`, `planLabel`, `planName` |
| `items[]` | Предметы; см. ниже |
| `lights[]` | Светильники из каталога (раздел 4) |
| `collisionRects[]` | Дополнительные препятствия для прогулки, [x0, y0, x1, y1] |
| `exterior` | `{type: "city", ground: -1050, facade: [...]}` — дома за окнами; `{type: "none"}` — только небо |
| `finishes` | `palettes` (свои палитры), `palette` (по умолчанию), `defaults`, `note` |
| `viewDefaults`, `views[]` | Виды для буклета: `id`, `title`, `eye`/`look` [x, y, z], `fov`, `open` (подписи механизмов или id предметов), `doors` (`open`/`closed`/`asis`), `lighting` |
| `plan` | `dims[]` — размерные цепи: `axis` (`x` — горизонтальный размер, `y` — вертикальный), `from`, `to` — координаты по этой оси, `at` — положение размерной линии по другой оси (по умолчанию над планом или слева), `text` (по умолчанию длина в мм), `rooms` — на каких страницах помещений показывать; `lines[]` — линии взгляда `{from, to, rooms}`; `hideIds` — скрыть подписи; `idAt: {"C12": [x, y]}` — перенести подпись предмета в точку плана |
| `sheet` | Лист плана A3: `title`, `subtitle`, `section`, `file`, `notes[]`, `footnote`; `box` — рамка плана [x0, y0, x1, y1] в см модели (по умолчанию стены плюс 60 см сверху под размеры, 5 см по бокам); `scale` — знаменатель масштаба (25 → 1:25), по умолчанию крупнейший из 1:20…1:250, при котором рамка помещается в поле 271 × 211 мм. Чем больше рамка, тем мельче масштаб |
| `booklet` | `title`, `file`, `footer`, `pages[]` — страницы буклета (раздел 6) |
| `checks` | `clearances[]` (`a`, `b`, `min_m`), `routes[]`, `targets{}` (точки маршрута), `occupied[]` (сценарии занятых мест), `skipRooms[]`, `radiusCm`, `gridCm`, `objects[]` |

Стороны стены: сторона +1 — справа по ходу от `a` к `b` на плане (ось y направлена вниз). Пример: у стены, идущей вправо, сторона +1 — вниз по плану.

### Предмет

```json
{ "id": "C09", "room": "cabinet", "label": "Книжный шкаф", "rect": [987, 434, 1025, 634],
  "type": "bookcase", "at": [1025, 434], "rot": -90, "width": 200, "depth": 38, "height": 225 }
```

- `id`, `room` и `label` у предметов, которые входят в план, ведомость и проверки. Декор (бумаги, лампы, розетки) пишется без `id`.
- `rect` — проектный габарит в плане. По нему считаются столкновения прогулки и подписи плана. Фактический габарит выгрузка снимает с геометрии.
- `collision: false` — предмет не задаёт стену для камеры прогулки и не входит в `check_layout.py`. Так помечают, например, кресло, задвинутое под стол. В сеточной проверке проходимости такой предмет остаётся препятствием, если его низ ниже 150 см: человек через кресло не проходит. Поэтому точки маршрута (`checks.targets`, `eye` помещений) ставить не ближе `radiusCm` (22 см) к любому предмету.
- `category` — заливка на плане: `seat`, `furniture`, `dark`, `equipment`, `wet`. По умолчанию определяется по типу изделия.
- `parts: [...]` — составной предмет из нескольких изделий каталога. Части наследуют `room` и `label`.
- `product` — паспорт реального изделия: `name`, `url`, `sizeCm` [ширина, глубина, высота], `tolerance` (по умолчанию 0,03). Выгрузка сверяет габарит модели с паспортом.

### Поворот корпусной мебели

Точка `at` — задний угол корпуса, от которого идёт фасад.

| `rot` | Корпус тянется | Фасад смотрит |
|---|---|---|
| 0 | вправо (+x) | вниз по плану (+y) |
| 90 | вверх (−y) | вправо (+x) |
| −90 | вниз (+y) | влево (−x) |
| 180 | влево (−x) | вверх (−y) |

## 5. Свои изделия: custom.js

Изделие, которого нет в каталоге, описывается функцией в `custom.js` проекта и вызывается из `project.json` по `type`:

```js
CUSTOM.receptionFront = p => {
  B(MAT.furn, p.x0, p.y0, p.x1, p.y1, 18, 115);          // брус по плану: x0, y0, x1, y1, h0, h1 (см)
  planSymbol({ kind: 'rect', rect: [p.x0, p.y0, p.x1, p.y1], category: 'dark' });
};
```

Функции видят всё ядро:
- `B`, `RB`, `CYL`, `blob` — брусья, скругления, цилиндры, контактные тени;
- `cabinet`, `officeChair`, `sofa` и другие построители каталога;
- `MAT` и `std({...})` — материалы, новый материал;
- `tex('ключ')` — текстура;
- `WX`, `WZ`, `S` — перевод плана в метры сцены;
- `G.interior`, `TOG` и `hinge(...)` — механизмы;
- `planSymbol` — знак плана, `rotOf` — поворот.

Правила для своих изделий:
- Строить конструкцию, а не декорацию: опоры на полу, детали с толщиной, зазоры фасадов, ручки, реальные соединения. Подробнее — `references/detailing.md`.
- Подвижное делать механизмом: `hinge`, `cabinet` с `doors` или `liftFront`. Тогда ход проверяется вместе с соседями.
- Повторяющееся в нескольких проектах изделие переносить в каталог (`engine/runtime/catalog.js`), а не копировать между проектами.

## 6. Выпуск и проверки

`make.py` выполняет шаги по порядку:

| Шаг | Команда внутри | Результат |
|---|---|---|
| `build` | `node build.mjs <проект>` | Тур HTML. Перед сборкой — проверка данных (`tools/validate.mjs`) |
| `export` | `node tools/export.cjs <тур> --out data` | `model.json` (предметы, двери, механизмы, знаки плана, паспорта, модели), `layout.json`, `routes.json` |
| `check` | `python3 tools/verify.py data --html <тур>` | `check_layout.py` навыка (стены, предметы, полный ход дверей, расстояния, маршруты), проходимость сеткой с открытыми дверями и стульями, дверцы, упёршиеся в стену, офлайн-тур |
| `views` | `python3 tools/views.py <тур>` | Виды из самого тура: headless Chromium, WebGL через SwiftShader, около 10 с на кадр |
| `docs` | `python3 tools/documents.py data` | Лист A3 (масштаб выбирается от 1:20 до 1:250), SVG плана, буклет A4 |
| `six` | `python3 tools/sixviews.py <тур> --data data` | Листы шести видов предметов (раздел 8) |
| `photo` | `python3 tools/photoreal.py <тур>` | Фотореалистичные виды в `images-cycles/` (раздел 9) |

Шаги `six` и `photo` выполняются только по явному списку `--steps`. Если шаг `docs` запущен без видов (`views` или `photo` не выполнялись), в буклете вместо снимков будут серые заглушки «нет снимка» — `make.py` предупреждает об этом.

Если сборка или выгрузка не удались, `make.py` останавливается и не проверяет устаревшие данные. Ошибка построения называет предмет: `items[12] (P03) cabinet: …`. Чтобы буклет собрался из фотореалистичных видов, после шага `photo` вызвать `docs` с `--images out/images-cycles`.

Страницы буклета (`booklet.pages[].type`):

| Тип | Содержание |
|---|---|
| `cover` | Вид `photo`, заметки `notes`, сноска `footnote` |
| `plan` | Общий план с подписями помещений, заметки; размеры — все из `plan.dims` или свои `dims`; `ids: true` — подписи предметов; `cameras` — точки видов; `box` — рамка |
| `room` | План помещения `room` (`box`, `planArea`, `cameras`, `dims`) и заметки |
| `views` | Два вида `photos[]` (`view`, `caption`, `title`) и полоса `band` |
| `roomPhoto` | Узкий план помещения и один вид с текстом |
| `materials` | Вид, образцы `swatches[]` (`color`, `title`, `body`), текст и сноска |

Что проверки не делают:
- не проверяют реальные сетки, движение между отсчётами угла и одновременное движение двух механизмов;
- не проверяют нормативы, свет и частоту кадров;
- кресло, задвинутое под стол, сплошным габаритом дало бы ложное пересечение, поэтому такие предметы помечаются `collision: false`, а их подход проверяется маршрутом.

Пустой список замечаний не означает «всё безопасно». Это значит только, что в проверенном объёме пересечений нет.

## 7. Готовые 3D-модели (GLB) и паспорт изделия

```json
{ "id": "G01", "room": "cabinet", "label": "Кресло для отдыха", "type": "glb", "src": "models/chair.glb",
  "at": [430, 330], "rot": 40, "collision": false, "expect": [82.7, 57.1, 68.6], "tolerance": 0.02 }
```

- **Встраивание.** Сборка встраивает GLB в HTML целиком и подключает загрузчик glTF (three 0.160, MIT) только при наличии моделей.
- **Посадка.** Модель встаёт на пол в точку `at`, центр её габарита совмещается с этой точкой; `anchor: "origin"` сохраняет начало координат модели.
- **Масштаб.** glTF задаётся в метрах. `scale` — явный множитель, если автор модели ошибся с единицами. Подгонять масштаб под ожидаемый размер нельзя: несовпадение и есть находка.
- **Паспорт.** `expect` — размеры производителя: ширина, глубина, высота, см. После загрузки габарит сверяется с допуском, результат попадает в `model.json → models` и на лист шести видов.
- **Лицензия.** Сохранять лицензию, автора и исходный URL модели. Проверено на SheenChair из glTF-Sample-Assets (CC0, Wayfair): 82,7 × 57,0 × 68,6 см, отклонение от паспорта не больше 0,2 %.
- **Ограничения.** Не проверялись: сжатие Draco/KTX2, скелетная анимация и варианты материалов KHR_materials_variants. Для подготовки, замеров и шести ортографических видов исходного файла можно использовать `scripts/asset-pipeline.py` навыка anatomy в Blender.

Паспорт есть и у изделий каталога: поле `product` у предмета. Предмет, повёрнутый не на угол, кратный 90°, сверяется только по высоте.

## 8. Лист шести видов

```bash
python3 $E/tools/sixviews.py out/<id>-tour.html --data out/data --items C09,R08 --out out/sixviews
```

Предмет изолируется в туре, остальная сцена скрывается. Снимаются виды с четырёх сторон плана, сверху и общий вид со стороны помещения. В шапке листа:
- габарит по геометрии модели;
- паспорт и отклонение от него, если паспорт задан.

На листе проверять силуэт, число и место опор, крепления, фасады и рабочие стороны. Эти вещи проверяются отдельно от кинематики и отделки. Скрытые у стены стороны тоже видны: например, белая задняя стенка холодильника в кофейном модуле. Решать, допустимо ли это, по месту установки.

## 9. Фотореалистичные виды (Blender/Cycles)

```bash
uv venv --python 3.11 /root/asset-runtime && uv pip install --python /root/asset-runtime/bin/python bpy==4.5.3 pillow numpy
INTERIORS_BPY_PYTHON=/root/asset-runtime/bin/python python3 $E/tools/photoreal.py out/<id>-tour.html --out out/images-cycles --size 1280x800 --samples 40
python3 $E/tools/documents.py out/data --images out/images-cycles --out out
```

Как это работает:
- `scene-export.cjs` выгружает сцену тура как есть: мировые треугольники, UV с применённым преобразованием текстуры, PBR-материалы с картами, светильники, солнце и камеры видов.
- `cycles_render.py` строит в Cycles солнце, небо через окна, прожекторы светильников и светящиеся поверхности. Включено шумоподавление.
- Виды группируются по состоянию механизмов: двери и открытые фасады выгружаются для каждой группы отдельно.
- Детали, которые стыкуются гранями в одной плоскости (короба наличников, рамы окон), Cycles затемняет в месте стыка: на кадре появляются чёрные квадраты. Поэтому при выгрузке каждый экземпляр сетки увеличивается от своего центра на свою величину, от 0,03 до 0,39 мм. Плоскости расходятся, а сетка остаётся замкнутой. Если чёрные пятна всё же появились, искать совпадающие грани в `custom.js`.
- Зеркальные детали (масштаб −1, например облицовка с обратной стороны стены) выгружаются с обратным обходом треугольников. Без этого нормаль грани в Blender смотрит против заданной, и стена выходит чёрной.

Установка и время:
- `bpy` 4.5.3 ставится в облачной среде из PyPI (около 370 МБ). Вместо него подходит Blender CLI: `INTERIORS_BLENDER=/path/to/blender`.
- На двух ядрах CPU кадр 800 × 500 при 24 сэмплах считается около 70 с, кадр 1280 × 800 при 40 сэмплах — около 5 мин.

Свет подобран коэффициентами `--sky 3 --sun 3.5 --lamp 18 --exposure 1.1`: это иллюстрация, а не светотехнический расчёт. Изображение не называть фотографией, а освещённость в люксах из него не выводить. Пропускаются:
- декали контактных теней тура — в Cycles тени настоящие;
- шейдерные эффекты: огонь, небо.

## 10. Ограничения и изменение движка

- **Что проверено.** WebGL проверен в headless Chromium через SwiftShader. Частота кадров на телефоне и поведение настоящих GPU не измерялись.
- **Где правится движок.** Ядро — `runtime/core-head.js`, `catalog.js`, `core-tail.js`. Скрипт собирает их в один HTML в таком порядке: three.js → текстуры → данные → ядро + каталог + custom.js + сборка сцены.
- **Как проверять правку ядра.** Сохранить тур примера офиса до правки, пересобрать и сравнить: `python3 tools/parity.py до.html после.html <папка>`. Расхождение по всем помещениям должно быть 0,00 %. Затем сверить `model.json` по габаритам и `verification.json` по проверкам. Изменения, которые меняют картинку намеренно, описывать отдельно.
- **Что такое движок.** Это производственная основа для повторяемой работы, а не универсальный 3D-редактор. Нестандартные изделия описываются в `custom.js`, детальные механизмы и разнесённые виды — в навыке anatomy.
